# Operations Runbook

## Service down
1. `kubectl -n taskflow get rollout,pods` - are pods Running/Ready?
2. `kubectl -n taskflow describe pod <pod>` - look for ImagePullBackOff, OOMKilled, failing probes.
3. `kubectl -n taskflow logs deploy/...` or Grafana Loki: `{namespace="taskflow"} | json | level="ERROR"`.
4. If a recent release caused it, roll back (below).

## High error rate
1. Grafana *TaskFlow - Service Overview*: which status/path is failing, since when?
2. Compare with deploy time: `kubectl argo rollouts get rollout taskflow -n taskflow`.
3. During a canary the AnalysisRun aborts automatically at <95% success; confirm with
   `kubectl -n taskflow get analysisrun`.
4. Check `FAIL_RATE` is `0`: `kubectl -n taskflow get cm taskflow-config -o yaml`.

## High latency
1. Dashboard p95/p99 panel; check HPA: `kubectl -n taskflow get hpa`.
2. CPU throttling: raise limits in `k8s/base/rollout.yaml` via PR (GitOps - never `kubectl edit`; self-heal reverts it).

## Crashloop
`kubectl -n taskflow logs <pod> --previous`; verify image tag exists in GHCR and probes paths are `/healthz`, `/readyz`.

## Rollback
| Situation | Action | RTO |
|---|---|---|
| Canary failing | nothing - Argo Rollouts aborts and keeps stable | ~1-2 min |
| Bad release already at 100% | Actions -> **Rollback** -> previous SHA, or `git revert <deploy-commit>` and push | ~3 min |
| Emergency | `kubectl argo rollouts undo taskflow -n taskflow` (then commit the same revert to Git or Argo CD will re-apply the bad tag) | <1 min |

## Disaster recovery
Everything is declarative: cluster = `terraform apply`, platform = Helm via Terraform, app = Argo CD sync from Git.
Rebuild from nothing: `./scripts/bootstrap.sh`. The only state outside Git is the (in-memory) task data, which is a known demo limitation.

## Secrets
No secrets are committed (gitleaks gates every push). Grafana password is generated by `bootstrap.sh` and passed as a sensitive Terraform variable.
